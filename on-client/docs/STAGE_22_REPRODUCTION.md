## 데이터 보존 계획

데이터 종류, 코드상 저장 계약, 기존 SQLite DB의 안전한 전체 백업 및 별도 복구 사본 절차, 사용자별 설정의 보존·복구 한계는 [22단계 데이터 보존 계획](STAGE_22_DATA_PRESERVATION.md)에 기록했습니다. 판정의 `data_preservation_plan` 요청에 바로 대응하는 저장 위치 확인 방법, DB 백업·별도 복구 절차, 운영 복구 한계 요약은 [데이터 보존 판정 보완](STAGE_22_DATA_PRESERVATION_ADDENDUM.md)에도 정리했습니다.

핵심 제한은 다음과 같습니다.

- 조치 DB는 호스트가 명시한 기존 SQLite 파일이며, 일반 `start-alekov.ps1` 실행만으로 활성화되지 않습니다. 실제 설정 경로를 모르면 DB를 검색하거나 백업하지 않습니다.
- SQLite 백업·별도 복구 사본 절차는 안내로 적었으며, 실제 실행·무결성 확인 결과는 없습니다. 과거 DB를 활성 DB로 덮어쓰거나 재집행하는 복구는 지원되지 않습니다.
- 사용자별 계정 설정은 프로젝트 밖의 Windows 사용자별 위치와 DPAPI·사용자/프로젝트 identity에 결속됩니다. 프로젝트 코드에서 검증된 export/import 또는 파일 복사 백업 절차를 확인하지 못했습니다. 원래 폴더·사용자 환경을 보존하며 다른 환경으로 임의 복사하지 않습니다.

## 지원 범위·미해결 사항

- `0.2.14`는 시작 틀 버전입니다. 이 기록의 상태는 **검증 중**이며 `v1.0` 또는 운영 인증이 아닙니다.
- 19단계의 실제 보안 조치 집행 연결은 제공 제품 안내상 미완료입니다.
- 이 기록의 데이터 보존 계획은 문서에 적힌 절차이며, 실제 DB 경로 확인·백업·복구나 사용자별 설정 복구를 실행했다는 뜻이 아닙니다.
- 새 복제본에서 실행 도구 시작, 브라우저 확인, 종료·재실행, 13~21단계별 기능 관찰을 수행하지 못했습니다. 제공된 일반 실행 오류는 안내된 원인·조치 범위에서 설명할 수 없습니다.
- 보완 문서의 새 AI 판정, 커밋·푸시·제출은 확인되지 않았습니다.
